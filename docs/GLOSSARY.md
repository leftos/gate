# Glossary

Terms the gate's docs use in a project sense, in alphabetical order.

- **Abandon**: the journal event a gate writes when Ctrl+C ends it while still queued, with the seconds it waited.
- **Abandoned slot**: a slot taken from a gate that died holding it, seen as an abandoned mutex or, when the take is clean, a claim whose pid and start are no longer alive; the next gate takes it as its own and journals the takeover.
- **Adoption**: the box taking the helper's suspended child by handle (`Suspended::adopt`), after checks on its pid, parent, creation time, session, image and suspended thread.
- **Alone**: a critical request or gate asked for `gate run --slot critical --alone` (`-Alone`): it holds the whole machine, the light slots a plain critical gate leaves beside it included, so its ticket says `alone: true` and the beside allowance is 0 while it waits or holds; its load snapshot is logged at the start and the end of the run, however the run ends.
- **Archive**: the gzipped `release` lines of a rolled journal, kept in `<state root>\archive\events-<stamp>.jsonl.gz` for 180 days; the gate whose append rolled the journal writes it before releasing the journal mutex.
- **Aside copy**: the old `gate.exe` an install moves to `gate.exe.<stamp>.<pid>.old` beside the new one; the install deletes older ones once the new gate.exe is verified (hashes right and answers `--version`) and no process holds them, and keeps its own as the last good gate.
- **Auto ceiling**: a `--timeout auto:<n>` ceiling, which treats `n` as a floor and resolves at each take to `max(n, ceil(3 x the command's adjusted p99))`, capped at 2147483647; with no adjusted p99 it is `n`.
- **Back commit**: the commit at the back ref, holding the files a routed command changed on the builder, with the run's snapshot as its only parent; a sync-back kept or applied it.
- **Back ref**: either `refs/gate-back/<key>` on the builder, where the box writes the commit of the files its command changed, or a local `refs/gate-remote/<key>-back` ref, that result kept by the gate when it could not apply it; the bridge commit's choice of parent skips the local one.
- **Backfill guest**: a waiting gate admitted, during a critical drain, onto a slot the critical gate lends, because its expected run ends before the drain's shadow end; one still running when the drain completes is killed and re-queued.
- **Backstop**: the watchdog's last limit, five times the ceiling in wall time (less time paused behind a critical request), whatever the load. A routed run has two: the builder's own, and the client's on the run call, 5 x the ceiling + 60 s of wall time.
- **Bare repo**: the builder's `<root>\<repo>.git`, one per repo name and shared by every key of that repo (the key names only the refs `refs/gate/<key>` and the work folder), which a routed run's push lands in.
- **Bare write**: a box git step that writes the shared bare repository (`update-ref -d` in the bare, `push`, `git init --bare`); it runs on a hidden console to its end or its bound and still starts after the client is gone or a stop came, since a killed one could leave a lock the box never removes.
- **Barrier**: the earliest live critical ticket that arrived before a gate's own, which holds the gate back: a heavy gate takes no slot behind it and a light gate a light slot only while fewer light gates than the beside allowance run beside the request.
- **Beside**: the nesting case of a gate started under a no-slot parent's marker (`Nesting::Beside`): the parent holds nothing to cover or lend, so the gate takes its own slot as a top-level gate would, a critical child included.
- **Beside allowance**: how many light gates may run beside a critical request, `min(2, light count)`, or 0 while an alone request waits or holds, a count whichever light slots those gates hold (`gate_state::beside_allowance`); a critical gate takes the other light slots.
- **Beside mutex**: the named mutex `Local\gate-critical-beside` (with the root hash under a non-default root) that a local light gate, a gate being lent a slot and a critical gate try once and hold around their count of the light gates, their take and their claim or lend marker, so a gate between its take and its claim is counted.
- **Black-box suite**: the Rust integration suite (`crates/gate/tests/suite/`) that drives the built `gate.exe` through its CLI and reads only its exit code, output, log, journal, claims and tickets; it needs the `test-seams` feature to run.
- **Bounded call**: a call of the Rust remote client to the builder's `gate box` that is not the run itself (the `stop` and the `boot` after a lost connection), ended after 30 s and retried once after a pre-banner failure while 5 s of the bound would be left.
- **Box**: a builder; the word the gate's prose and its hidden `gate box` subcommand use.
- **Box job**: the named job `Local\gate-remote-<key>-<12 hex>` (`gate-remote-<key>-<12 hex>` on a macOS builder) that a `gate box run` puts its command in, named by the payload and stopped by `gate box stop`; it has no limits and no kill-on-close.
- **Bridge commit**: a commit with a snapshot's tree whose parent is the previous snapshot, which the Rust remote client builds so a push can send only what changed; none when there is no previous snapshot.
- **Brought-back glob**: an output glob of a routed run that brought everything back; a file one matches is never a stale folder's.
- **Build id**: the text between the first `+` and the next `+` or the end of the gate's version (`gate --version` prints `gate <package version>+<build id>`, plus `+seams` for a `test-seams` build): the 12-hex head commit of the build, `<12-hex>-dirty.<8-hex>` for a build of changed tracked files (the 8 hex are the first 8 of the SHA-256 of `git diff HEAD --binary`), or `dev` for a build `tools/install.ps1` did not make with a commit. The client compares the whole version text, so another build of one package version is another version.
- **Build server**: a long-lived compiler or MSBuild node process (`VBCSCompiler`, a `dotnet` running `VBCSCompiler.dll` or an MSBuild node) that builds share.
- **Builder**: a remote machine, Windows or macOS, named in a PC's own `remote.json`, that runs routed heavy commands with its own copy of `gate.exe`.
- **Builder setup**: what makes a machine a builder, in two halves: claude-config's private provisioning (first boot, WSL, Defender, Developer Mode, the event log ACL, autologon, the Dev Drive, OpenSSH, Windows Update policy) and this repo's `tools/builder/install-toolchains.ps1` (toolchains, sccache and WSL keep-alive tasks, git config, MSYS keeper, the work-folder prune task, and the work root with its protected owner and DACL); see [routing-a-repo.md](routing-a-repo.md#builder-setup).
- **Builders entry**: an element of `remote.json`'s optional `builders` array, `{host, os, root, slots, routed, repos, outputs}`, naming a further builder a routed run can go to: the first routed entry in file order whose own `repos` patterns match, else `host`; `Builder` in `gate-router`.
- **Builders list**: the builders `gate push` reaches: `host` of `remote.json`, then each entry of its optional `hosts` in file order, an entry equal to an earlier one in any letter case skipped. An unpinned run routes to `host` and the routed `builders` entries, never to a `hosts` entry, which only a run pinned with `gate run --builder` reaches. A `builders` entry with `os` `macos` is pushed to as well, after them, by building its `gate-box` there.
- **Burn**: `gate burn`, one process that spins a number of threads on the CPU for a set time at the priority it inherited, taking no slot and enforcing no 120 s cap (it allows up to 180 s); the load-burn tool runs it inside a critical gate and applies the 120 s cap. `gate run --burn` is the planned owner of the slot, the command and the cap (GATE-160).
- **Ceiling**: the `--timeout` limit, as given or, for an auto ceiling, as the take resolved it; passing it kills the command as TIMED OUT. A local run counts it in load-adjusted seconds on this PC; a routed run counts it the same way on the builder, from the command's start, the push and the fetches being counted by the transfer ceiling.
- **Ceiling hint**: the line `gate: the ceiling <n> is below this command's load-adjusted p90 of <p90>`, said after the expected-time line when the resolved ceiling is under the estimate's adjusted p90; the line `gate: ceiling <n> (3x ... p99 ..., above the given <floor>)` beside it says history raised an auto ceiling.
- **Check**: `gate check`, which says what this PC lacks for the repo in the current folder (the manifest's tools, the `global.json` SDK pin, the declared siblings, the builder warm-up) as `check: here: ` lines with an `install: here: ` hint per missing or too-old item, and installs nothing; with `--builder <host>` it asks one builder through the box's preflight and words the lines `check: <host>: ` and `install: <host>: `; not the parity check a routed run's preflight makes.
- **Checkout filter**: a `filter` driver (or `ident`) that a path's git attributes put its worktree file through; a sync-back that writes or deletes such a path is refused, since `git apply` would run the user's filter program on it.
- **Chosen Godot version**: the version, `x.y.z`, of the builder's Godot install that a routed run uses, picked after the preflight from the repo's Godot pins among the versions the builder reported (a partial pin picks the highest install meeting it; no pin, or `""`, picks none) and sent as the payload's `GodotVersion`.
- **Claim**: the JSON file `slots\<name>.json` a gate writes while it holds a slot, naming its pid, command, log and ceiling.
- **Closes its lends**: said of a critical gate that holds every slot it takes while lent gates still run: it rewrites its ticket with `lendsClosed: true`, so no light parent lends its slot again and the gate waits only for the lends already made.
- **Cold**: said of a builder work folder that no matching warm-up has warmed, a new one above all; a routed run goes to it anyway, as a [cold run](#cold-run) when the folder is new. The journal's fallback reason `cold` is still read but no run writes it.
- **Cold run**: a routed run whose builder work tree its own preflight laid out (`gate: remote new work tree`), other than a warm-up; its ceiling is raised to `min(2 x ceiling, ceiling + 1800 s)`, it says the cold note, gets no hang hint, and its `release` carries `"cold": true`, which the history rows (`HistoryRun`) carry as `cold`.
- **Commit run**: a gated `git commit` (first word `git`, first non-option word `commit`), which holds the heavy or light slot its caller asked for, light for `--slot none`, for its whole command, hooks included, and hands its hooks `GATE_COMMIT_SLOT`; it never routes ([design.md, Critical drain and nesting](design.md#critical-drain-and-nesting)).
- **Compatibility layer**: `gate.exe`'s acceptance of the PowerShell gate's argument form (`-Log`, `-TimeoutSeconds`, `-Slot` and the rest), kept until no caller uses it.
- **Confirmation window**: the 5 s across which every scan of the cutover's drain must find no PowerShell gate before it ends, because the PowerShell gate deletes its ticket when it takes a slot and writes its claim up to about 2 s later; a scan that finds a gate resets it.
- **Console donor**: the hidden system `cmd.exe /d /q /k` that `gate box run` puts in the command's job, whose console the box sets to UTF-8 and the command inherits; it lives until the wait for the command is over.
- **Console keeper**: the `cmd.exe` `gate box run` starts on its own console while it is away on the donor's console, so its own console stays alive for it to return to (not the **MSYS keeper**).
- **Console session**: the Windows session attached to the builder's physical console, which the box reads (its id, connect state, user, domain and lock state) to judge whether a desktop run's command can start on that session's desktop.
- **Copy**: an item of an outputs archive's list marked `"copy":true`, a path whose bytes the archive does not hold because an earlier member or a file the PC holds (by the manifest, outside the run's back commit) has the same SHA-256; it carries `modified`, the box file's last write, and the install makes it in the stage from that member or file.
- **Cores hint**: the line before the passed line saying how many cores a command kept busy when its slot kind did not fit: a light run over 2 cores, a heavy run under 1.5 with cores to spare, or a no-slot run at 1.5 or more.
- **Covered**: said of a nested gate whose parent's slot kind covers its own (heavy covers heavy, light and none, light covers light and none, critical covers all), so it takes no slot. The covering parent may be a lent gate, which holds no claim of its own: it hands its command a heavy marker naming itself.
- **Covered marker**: the file `covered\<pid>-<start>.json` a covered gate keeps while it runs, so ops-tower sees a gate that writes no claim or ticket.
- **Critical drain**: a critical gate's wait for the gates that arrived before it to free their slots, while it holds back the gates that arrive after it.
- **Critical gate**: a gate run with `--slot critical`, which takes every heavy slot and every light slot but the beside allowance and runs its command at High priority.
- **Critical request**: a critical gate's queued ticket and run, from its arrival until it releases the machine; critical requests run one at a time in arrival order.
- **Cutover**: switching a machine's gates from the PowerShell gate to `gate.exe`; `gate cutover` runs the local one.
- **Cutover flag**: the file `%LOCALAPPDATA%\gate\cutover.flag`, whose existence tells ops-tower's state to read `gate.exe`'s files; the launcher does not read it.
- **Cutover sweep**: the change of every calling repo from the PowerShell launcher to the slim wrapper (`tools/gate.ps1`), after which the PowerShell gate is deleted.
- **Declarations folder**: the PC-owned folder `remote.json`'s `declarations` names for a repo, holding the `.gate/toolchain.toml`, `siblings.toml`, `desktop.toml`, `local.toml`, `env.toml` and `warmup.toml` the repo cannot commit; a file is read from it only when the repo has none of that name.
- **Declared local**: the `notRouted` journal word of a matched command a repo's `.gate/local.toml` keeps on this PC, by a pattern its words match or by a file the gate cannot use.
- **Delete pending**: a file marked for deletion when its last handle closes (the classic delete, not the POSIX one `fs::remove_file` takes); until then its name stays listed and every open or delete of it is refused with access denied, so the gate passes it over as going away.
- **Deny-only**: the state of a token group that still matches deny entries in an access check but no longer matches allow entries; a routed command's token holds the ssh logon's NETWORK group so.
- **Departed member**: a process the run's job held that has ended, as the job's completion port remembered it (pid, start, read while its process object lived, and exit time; one found gone, its start never read, is not remembered); a process that names its pid as parent and started within its lifetime, from the job's creation at the earliest, counts as escaped, so a kill reaches it though no sample saw it under a live member.
- **Desktop command**: the command of a desktop run, created by the desktop helper on the builder's interactive desktop and adopted by the box into the run's job, in place of the process the box would start itself in session 0.
- **Desktop declaration**: a repo's `.gate/desktop.toml`, whose `patterns` name the routed commands that need the builder's desktop; a routed run asks for it only when the first declared pattern its words match is also listed for the repo in `remote.json`'s `desktop`.
- **Desktop helper**: `gate-desktop-helper`, the Windows-subsystem exe a scheduled task starts in the builder's logged-on session at the box's request, which connects to the box's control pipe, creates a routed command suspended on the interactive desktop (`DesktopLaunch`) with the box's output pipes, and reports it for the box to adopt.
- **Desktop run**: a routed `gate box run` whose payload sets `Desktop` true, so its command is to run on the builder's logged-on desktop; the box refuses it with the `desktop` tag when it cannot.
- **Desktop stage**: the box's step after the checkout and the restores in a desktop run: it resolves the program and the run's Godot, takes the machine-wide desktop lock within the run's wait and reads the console session again under the lock, before any hand-off to the helper.
- **Desktop task**: the Task Scheduler task `\gate\desktop-helper` that `gate box register-desktop` registers on a builder (`gate push` runs it on every builder after installing the helper; it can also be run by hand over ssh), which starts the desktop helper in the logged-on user's session when the box asks.
- **Diagnostics block**: the record of what was running that a kill writes to the log before it terminates the job: the job's processes, the descendants outside the job and the last samples.
- **Drain**: see critical drain.
- **Drained cutover**: a cutover in which every gate of the old generation finishes before the switch completes, while the two generations share the slot mutexes and take turns on them.
- **Drive-relative path**: text of a letter and `:` not followed by `\`, `/` or `:` (`C:..\x`), which Windows resolves against that drive's own current folder; the router counts it outside the worktree wherever it appears at a path start.
- **Durations key**: the name a run's durations are filed and estimated under, `{place}:{class}:{repo[/sub]} | {normalised command}`, the repo being the main checkout's folder name, so every worktree of a repo shares it; it is made by `gate_state::duration_key` and differs from the history key, which is the normalised command alone, with no place, class or repo.
- **Durations store**: the file `durations.json` in the state root, holding for each key the newest passing runs (at most 30), its failure count (runs of any verdict but `passed`, except `unknown` and `transfer-timed-out` runs, which count nowhere) and its newest release; the estimate is made from it. A missing, stale or unreadable one is rebuilt from the journal and the archive.
- **Dynamic name**: one of cmd.exe's built-in variables (`%CD%`, `%RANDOM%`, `%ERRORLEVEL%` and the like), or one it sets for itself when its block lacks it (`%COMSPEC%`, `%PATHEXT%`, `%PROMPT%`), that it expands though the environment block holds no such variable; a batch target's words are refused when they hold one.
- **Elevated**: a process whose token is an administrator's full, unfiltered token; a routed command runs non-elevated, on a restricted copy of the builder session's token.
- **Engine env**: the names a `.gate/toolchain.toml` `[env]` table lists (`NAME = "unreal"`), sent as the payload's `EngineEnv`; the box sets each, for every command of the run, to the folder `UE_ROOT` gets, and removes an inherited value of each when the run chose no engine.
- **Env declaration**: a repo's `.gate/env.toml`, whose `prefixes` name the caller's variables its commands read; a routed run's dropped-variable line also names the caller's variables starting one, and never sends them without `--env`.
- **Escaped process**: a process outside the command's job under a process the job holds, such as a packaged desktop app a non-packaged descendant started, or what that app started; the watch counts their CPU as the command's own, and a kill of `gate run` ends them.
- **ETA**: the end of a wait line (`, the first frees in about 4 min`) saying when the soonest holder of the slots a gate waits for frees its slot, from its claim's `started` plus `expected.p50`; a critical gate's line says `the last`, the latest holder, since it needs them all. A holder past that end is `the first is 3 min past its usual 4 min, ceiling 15 min`, with the claim's ceiling; no ETA is said unless every busy slot's claim carries `expected`.
- **Exact key**: the durations key with a command's filter values kept (`{place}:{class}:{repo[/sub]} | {normalised command}`); the estimate uses it when it has enough passing runs, else the family key.
- **Exact pin**: a `.gate/toolchain.toml` entry (`godot`, `unreal`) met by an installed version equal to it on the parts it gives (`"5.8"` matches any 5.8.x), where every other entry is a minimum; `""` means any version.
- **Expected (field)**: the optional last field `expected: {p50, p90, n, key}` of a claim and a ticket, the durations store's estimate for the run's key (seconds to 3 decimals); absent for a run without history. The wait lines' ETA reads it from the holders' claims.
- **Expected-time line**: the `gate: expected about ... (usual ..., p90 ..., <n> runs)` line a run that takes a slot says once its claim is written, from the durations store's estimate for its key; nothing for a key with fewer than 5 passing runs.
- **Fallback**: a routed run that goes on after its builder refused it, the remote pool stayed full or the remote client could not start: to the next capable builder when the reason is one worth another builder (see Later builder), else to run locally; journalled as a `fallback` event with its reason, one per attempt.
- **Fallback poll**: the short timeout on every slot wait, which re-reads counts and tickets so a dead waiter's ticket is cleared even when no wake event comes.
- **Family key**: the exact key with each filter value replaced by `<filter>`, so runs of one command with different filters count together; an estimate from it is marked as such.
- **Fault seam**: the environment variable `GATE_DESKTOP_TEST_FAULT` of a `test-seams` build of the desktop helper, which names one step of its run to break (`exit-before-hello`, `hang`, `wrong-version`, `lie-handle`, `exit-after-create`); absent, empty or unknown is no fault.
- **Folder id**: a folder's volume serial number and 128-bit file id, read from an open handle; two sibling names with one id are one folder, as is a sibling that is the worktree's own folder.
- **Free share**: the fraction of the cores the command could use that other work left free in a sample, at least 5%; the load-adjusted clock advances by it.
- **gate-box**: the bin of the `gate-box-unix` crate, the gate box of a macOS builder (the Unix box); called as `gate-box box <verb> --stdin`, it speaks the wire of `gate box`.
- **GATE_COMMIT_SLOT**: the variable a commit run gives its command, holding the run's own slot marker, so a gate in its hooks can tell it runs in a commit's hooks ([Commit run](#commit-run)).
- **GATE_UNREAL_ROOT**: the builder's environment variable naming a folder of side-by-side Unreal Engine installs, one subfolder per canonical `x.y.z` version, each read from its `Engine\Build\Build.version`; the unreal probe lists them and a run with an `UnrealVersion` resolves `<root>\<version>`.
- **Generation**: the PowerShell gate or `gate.exe`, as `gate-state` tells them apart (`Generation`): ops-tower reads the PowerShell gate's files until the cutover flag exists and then `gate.exe`'s, plus the PowerShell claims of a slot whose mutex is open.
- **Git home**: the suite's own git config folder, `target\tmp\git-home`, that `HOME` and `XDG_CONFIG_HOME` name for every git a case or harness helper starts, so none reads the developer's global config.
- **Git hook**: as the router uses it, a gate whose environment has a non-empty `GIT_INDEX_FILE`; it stays local unless `remote.json`'s `hooks` names its repo.
- **Git place**: where git finds a pair's repository: its top folder, its git folder and its common git folder, asked once with a ceiling at the pair's parent and checked (the top folder is the repo's root, no two repos share a common folder); every later git call about the repo is given them outright.
- **Godot console word**: a command's first word that is a bare name (no directory part) whose name, after one trailing `.exe` is removed, matches `godot*console*` ignoring ASCII case with no `.` after the last `console`; the box runs the chosen version's `Godot_console.exe` for it.
- **Godot pin**: the Godot version a repo requires of a routed run's builder, from its `.gate/toolchain.toml` `godot` entry or the `Godot.NET.Sdk/<version>` its `*.csproj` files name; met when one of the builder's installs equals it on the parts the pin gives (`4.7` is any `4.7.x`), not as a minimum.
- **Hand-off**: the box's passing of a desktop run's command to the desktop helper: it starts and checks the helper, sends the command, takes the child the helper reports into the run's job and sees it to its end, with the failure ending (drop the pipe, wait for the helper, end it, sweep) when a step fails.
- **Hang guard**: a suite case's bound far past anything a loaded PC reaches (a 600 s sleep, `GIT_HANG_GUARDS`' 3600 s git limit and 600 s drain), so only the behaviour under test ends the case and a starved gate is late, never wrong.
- **Hang hint**: the line `gate: still running after <n>, <k>x its usual p90 of <p90>`, said once when a run passes 3x its estimate's p90 (never for a p90 under 1 s); it kills nothing.
- **Hash cache**: the file `remote\<key>.outputs-hashes` in the state root (`remote\<id>\<key>.outputs-hashes` for a `builders` entry, `<id>` its 8 hex digits), the outputs manifest line of a worktree's last built manifest, holding only its files last written at least 2 s before that build, and the files a complete outputs install put in place, at the stamp it read after the move and the hash it verified. The inputs have a cache of their own, `remote\<key>.inputs-hashes`, of the last built inputs manifest.

  The next build takes the hash of each file whose size and last write, as the open file's handle reads them, still match from it instead of reading the file, except while the pending marker stands.
- **Heartbeat**: a line printed so a gate around the printer does not read quiet as a stall; the wait heartbeat is a waiting gate's `still waiting` line every 30 s, and the box heartbeat is the `gate-remote-heartbeat: <cpu ms>` line a box (the Windows box wrapper, or the Unix box every 5 s) writes while its command's CPU use earns one.
- **Heavy**: the slot kind for work that keeps several cores busy; its pool's thread budget is 4.
- **Held folders**: a pair's root parent, root, siblings and their `.git` entries (and each repo's git and common folder) opened by the client without delete sharing from the check until its last push is saved, so none can be renamed, removed or swapped for a link meanwhile (`remote/held.rs`).
- **History key**: a journal run's `command` after `gate_state::normalize_command`: split with the C runtime's argument rules, tree flags and their paths dropped, `.tmp` and worktree paths shortened, each word re-quoted; runs with the same key count together.
- **Holds the machine**: said of a critical gate once it has taken every heavy slot and every light slot but the beside allowance, and no gate runs lent a light parent's slot; its ticket then says `holds`.
- **In-box gate**: a gate started inside a routed run's box job, trusted by `GATE_BOX_JOB`: it takes no slot and runs its command under its own watchdog ([design.md](design.md#critical-drain-and-nesting)).
- **In place**: said of an outputs archive member whose PC file changed during the run but holds the member's exact bytes (the same size and SHA-256), or of a member the install rewrites to the PC's roots (`MvcTestingAppManifest.json`, the coverage roots files) whose PC file a PC writer changed or made during the run, since that file already records the PC's roots: the install leaves it as it is, counts it in no `gate: outputs:` total and says nothing of it.
- **Input**: an ignored file of a repo's worktree that a routed command needs and the snapshot lacks, named by the repo's `inputs` globs in `remote.json` and sent by the remote client (a diff call, then a put call of an archive of what differs) and installed in the builder's work folder by `gate box inputs`; a run that cannot send them falls back with reason `inputs`.
- **Input desktop seam**: the environment variable `GATE_DESKTOP_TEST_INPUT_DESKTOP` of a `test-seams` build of the desktop helper, whose value the helper reports as the input desktop's name in its hello and still judges against `Default`; the suite's desktop cases set it to `Default` so they pass in a builder's session 0, and an empty value names the empty desktop.
- **Inputs record**: `{Work}.inputs` beside a work folder's lock, a JSON line holding the digest of the inputs manifest last installed and, per installed input, its path, size, SHA-256 and the last-write time and file id the box left it with; a kept entry (`{"kept": true}`) is a stale input a put left in place, still listed in the exclude file.
- **Inputs stage**: the folder `<root>\inputs-stage\<key>-<nonce>` (`inputs-stage-medium` on an unelevated box), made protected, where a put unpacks its archive before any input is moved into the work folder.
- **Install tripwire**: the box's check, before any verb runs, that its own gate.exe (and, at the preflight and the desktop hand-off, the desktop helper beside it) is installed where only administrators and SYSTEM can change it; a failure says `gate: the builder's gate install is not trusted: <why>`, and the PC falls back to a local run with reason `install`.
- **Interrupt**: a Ctrl+C or Ctrl+Break at the gate's console, which stops a queued gate or a running command (exit 0xC000013A unless the command exits on its own first).
- **Interrupted-command clear**: what a run does on the builder, before it lays out its work folder, when `{Work}.command` is there (a command was killed at its ceiling or lost its connection). It ends the recorded job, removes the files written in the folder since the recorded start (a `.git` skipped) and the records `.warm`, `.packages` and `.tools`, and removes its own record last. A layout change clears the whole folder instead. The run after it is cold ([design.md, The box side](design.md#the-box-side)).
- **Job record**: the Unix box's file `<Work>.pgid` (`<Work>.tools.pgid` for a tool restore), written whole by atomic replace and holding the job's name, the decimal process group and the decimal session id, one per line, which `stop` reads to end the group; the runner writes it for each git step and removes it once the group has ended.
- **Journal**: the append-only `events.jsonl` in the state root, one JSON line per gate event (`queue`, `take`, `release` and others), with its rolled file and gzip archive.
- **Journal mutex**: the named mutex `Local\gate-journal` (with the root hash under a non-default root) that every gate holds, waiting up to 2 s, while it appends to the journal, rolls it and archives.
- **Judging glob**: an output glob that decides which folders the stale line may name: the run's `outputs` (the defaults when the repo's entry is absent or `[]`) and the defaults `**/bin/**` and `**/.godot/mono/temp/bin/**`.
- **Key folder**: the work folder one work-folder key names (`{root}\work\{key}`), with the records beside it, `{key}.<extension>` for the lock, warm, layout, inputs, sent-build, tools, packages, index and command records (the nine kinds the box's prune knows); a prune removes an idle one whole except its lock.
- **Key version**: `keyVersion` in the durations store, naming the rule set that made its keys; a store written under another one is rebuilt.
- **Late arrival**: a PowerShell gate whose earliest claim or ticket `since` is later than the cutover flag's write time, because its caller bypassed the launcher; the cutover's drain names it.
- **Late take**: the slot of its own kind that a covered gate takes, beside its running command, when its parent gate ends first; its `take` names the ended parent in `parentPid`.
- **Later builder**: a builder a routed run may try after the one it was sent to fell back (`RemoteRun::later`, held by alias): each other `builders` entry whose patterns match the command, in `remote.json` file order, then `host`; each is built from the routing file when it is tried, and one that cannot be is skipped with a log note.
- **Layout name**: a folder name the builder can lay out beside another (`gate_router::is_layout_name`): ASCII letters, digits, `.`, `_` and `-`, not starting or ending with a dot, not a reserved device name; a sibling's name and a root's folder name that declares siblings must be one.
- **Layout record**: `{Work}.layout` beside a work folder's lock, naming how the folder is laid out: `single` (one repo checked out in the folder itself), `pair {leaf} {siblings}` (the siblings sorted ignoring case) or `changing` while the folder is cleared; the run clears the folder when the record names another layout than its own.
- **Lend marker**: the file `slots\gate-lent-<parent pid>-<pid>-<start>.json` a lent gate keeps from before its command starts to after it ends, in the claim's format (kind heavy, index 0); a critical gate holds the machine only once no live one remains.
- **Lending**: a light parent gate, on any light slot, letting a nested heavy gate, which its slot does not cover, run on that slot while a critical request drains, instead of queueing behind it; the gate is the lent gate. It ends once the request closes its lends or holds the machine. The lent gate hands its command a heavy marker naming itself, so the gates nested in it are covered.
- **Lent window**: the span during a critical drain in which the critical gate lends one slot to backfill guests, ending at the shadow end.
- **LFS scratch folder**: the protected folder `{root}\lfs-run\{key}-{nonce}-{16 hex}` the box makes for a run that carries an `LfsDigest` or whose snapshot's `.gitattributes` name the LFS filter, used as git-lfs's `lfs.storage` for the run's checkouts and back commit and removed when the run ends, so no smudge or clean touches the work folder's `.git\lfs` or the LFS store ([design.md, Routing](design.md#routing), Git LFS).
- **LFS store**: the protected folder `<Bare>\lfs` beside a routed repo's bare repository on a builder, holding the Git LFS objects its routed runs' pointers name, each installed only by `gate box lfs` after its SHA-256 and size were checked; the checkout's LFS filter reads it through the work folder's alternates ([design.md, Routing](design.md#routing), Git LFS).
- **Light**: the slot kind for work that keeps one or two cores busy; its pool's thread budget is 2.
- **Load-adjusted time**: wall time scaled by the free share in each sample, the clock the ceiling runs on, so a command slowed by other work is not killed for it.
- **Lock sweep**: the removal, before a box run's or lay-out's first git step, of each tree's `.git\index.lock`, `HEAD.lock` and `config.lock`, `{Work}.index.lock` and the bare's `refs\gate-back\<key>.lock`, left by a git that was ended; done through handles held one folder beneath another, never following a link, skipping a lock another handle holds open.
- **Log cap**: the most bytes of one remote call's output, its standard output and standard error together, the remote client writes to the gate's log (256 MiB); past it the log gets one `gate: the builder's output passed 256 MiB; the rest is not logged` line and the console keeps echoing.
- **Log hash**: the first 16 hex digits of the SHA-256 of a lower-cased, normalised absolute log path, carried in the name of that log's mutex.
- **Lost connection**: a remote run call that ended with ssh's status 255 after the banner (or whose command itself exited 255); nothing is synced back, the client sends the stop, and a boot-time check tells a restarted builder from a dropped link.
- **Machine consent**: the `siblings` list in `remote.json` for a repo, naming the sibling folders this PC lets that repo's routed runs carry; a sibling `.gate/siblings.toml` declares but the list does not name exactly keeps the run here.
- **Manifest**: the PC's list of its files under a routed run's output globs (path, size, last write, SHA-256), sent to the box so it packs only the files the PC lacks or that differ.
- **Marker**: a failure marker, a log line the built-in regex reads as a failure (such as `Build FAILED.` or `error CS1234`), which turns a zero exit into status 1.
- **Moved aside**: said of a folder found where the box must write a file (`.git\info\exclude`, `.git\objects\info\alternates`), or the LFS store's `{Bare}\lfs` when it has the shape a plain git-lfs `CreateDirectory` leaves: renamed beside itself to `<name>.gate-moved-<n>` (`n` 1 to 100, never replacing an entry) and never walked, since another account may have filled it; the box says `gate: remote moved aside the folder <old> to <new>`, with `: its owner, DACL or label was not the box's` after the store's.
- **MSYS keeper**: the `cat.exe` from Git's `usr\bin` that `gate box run` keeps running for a whole run or warm-up, started once the work folder's lock is held and answered once before the checkout, so Git's shared MSYS section is set up before any Git shell of the run starts and no killed start-up can leave its lock held (not the **Console keeper**).
- **Need**: in the parity check, what a snapshot needs that the builder lacks: one `Need` of a kind (so far the .NET SDK), each said on its own mismatch line. The preflight payload's `Needs` key is wider: every tool the PC wants probed with its minimum version, whether the builder has it or not.
- **Nesting**: a gate started inside another gate's command (a build hook under a gated `git commit`), which reads its parent from the slot marker.
- **netfx-sdk**: the tool name for the .NET Framework SDK `UnrealBuildTool` looks for, which a manifest naming `unreal` needs at 4.6.0 or later; the box reads it from the registry rather than running a program, and lists every installed version.
- **No slot**: the slot kind `none` (`--slot none`), for a command that only dispatches or watches remote work: it takes no slot, mutex, ticket or claim, never waits, and still has its job, log, ceiling and watchdog.
- **Not-routed builder**: a `builders` entry with `"routed": false`, which no unpinned run picks or tries and `gate push`, `gate check --builder` and a pinned run reach; the way to trial a new builder.
- **Notes**: the gate's own lines gathered while a run goes and appended to the end of its log.
- **Nothing-back record**: the JSON file `remote\<key>.nothing-back` in the state root, left by a routed dotnet build that ended on the builder without its outputs known to be brought back, or, when none stands, by a routed dotnet `--no-build` command whose word was dropped on the builder; while it stands, a local dotnet `test` or `run` drops its `--no-build`.

  A passing local build of the whole worktree with the same configuration, framework and runtime removes it, and so does a passing routed build of that kind that brought all its outputs back; a routed `--no-build` command never clears it.
- **Open run**: a journal run that took its slot, has not released or abandoned it, did not run on its parent's slot, and whose gate is live by pid and process start; the history's `open` list holds every one, uncapped.
- **Output cap**: the remote client's limit of 64 KiB on one line of a call's output (a `\r` resets the line, so git's progress counts per update), which kills a capped call that sends a longer one.
- **Outputs archive**: the `<key>-<nonce>.tar.zst` a routed run's changed output files travel in, its last member `.gate-outputs.json` listing every path it brings back, in pack order, the files before it and the copies that have no member.
- **Outputs cap record**: the file `remote\<key>.outputs-capped` in the state root, `{"v":1,"hits":<n>}`, counting a worktree's routed runs in a row whose outputs fetch passed the fetch cap; the first hit keeps the pass, a second in a row fails the run, and any other end of its outputs fetch but a Ctrl+C during it, or a box that packed nothing, removes it.
- **Outputs manifest**: the Manifest of the PC's files under a routed run's output globs, as the Rust client builds it before the run call and writes it as one line on that call's stdin, for the box to read.
- **Outputs stage**: the folder `<worktree>\.tmp\<key>-<nonce>` a fetched outputs archive is unpacked and checked in before any file is moved into the worktree.
- **Outputs-pending marker**: the empty file `remote\<key>.outputs-pending` in the state root, written before a routed run's run call (for a run with output globs, or a dotnet `--no-build` command whose outputs were withheld, whose marker no end of that run removes) and removed after an accepted `gate-remote-outputs: 0`, an install that skipped no file or only files it cannot rewrite, or an install refused for what the archive's members are; while it stands, the next run sends `OutputsFull`.
- **OutputsFull**: the run payload's flag, true when the outputs-pending marker was there, that asks the box for every output that differs from the PC's, not only those the run changed.
- **Package restore**: the box's install of a repo's pnpm, bun or npm packages in the folder holding the lockfile, before a routed command of that manager (`pnpm`; `bun`, `bunx`; `npm`, `npx`), skipped while the packages record holds the folder's hash and `node_modules` is there.
- **Packages record**: the file `{Work}.packages` beside the work folder's lock, one `{folder}\t{hash}` line per folder whose pnpm install passed, `bun:{folder}\t{hash}` per folder whose bun install passed, or `npm:{folder}\t{hash}` per folder whose npm install passed (a folder holds one manager's line), the hash over that folder's package files; the box skips the install while the line matches and `node_modules` is a folder.
- **Pair**: a run's main repo and its siblings as the box lays them out, the payload's `Pair` (`Leaf`, the main checkout's folder name, and `Siblings`): each repo has its own bare repository and tree, `Work\{leaf}` and `Work\{sibling}` (`Work/…` on the Unix box), and a commit from `Snapshot` or `SiblingSnapshots`.
- **Pair key**: a sibling pair's single work-folder key, the main checkout's (`<repo name>-<8 hex>`, `gate-wire`'s `is_key_of` and `trees`); its siblings have no key or builder folder of their own, only their own bare repository's refs under that key.
- **Parity refusal**: the `parity` refusal of a routed run whose builder lacks the .NET SDK the snapshot needs (its `global.json` pin under the rollForward policy, or, with no pin, an SDK of this PC's newest major); the run goes local.
- **Path form**: the path rules a box reads its payload under (`gate-wire`'s `PathForm`): `Windows`, a drive path compared as a full path without case and joined with `\`, job names starting `Local\`; `Unix`, an absolute path in its one spelling (no `\`, no empty, `.` or `..` name) compared byte for byte and joined with `/`, job names without `Local\`.
- **Path map**: the `-p:PathMap=<box tree>\=<PC root>` word the gate adds to a routed dotnet build's words, one pair for each tree of the run (pairs joined by `%2C`), so the dll and pdb the builder compiles record the PC's paths and equal a local build's; left off when the caller sets `PathMap`, `ContinuousIntegrationBuild` or `DeterministicSourcePaths` itself, or when a PC root holds a character the builder's command line cannot carry.
- **Path start**: a place in a command word where the router judges a path afresh: the word's start, after white space or a line break, after `, ; " ' ) | & < > ( =`, after a leading `@`, and after the colon of a switch that starts its token or follows a `"`, `'` or `,`.
- **Pause marker**: an empty file a gate under a parent gate's slot rewrites on every pass while it waits behind a critical request, which stops its parent's watchdog clocks for that time, the watchdog reading it on each sample; one older than 30 s is stale.
- **Payload**: the JSON object a `gate box` verb reads its inputs from (paths, `Nonce`, `Command`, `Needs` and the like), sent base64-encoded as the request.
- **Pinned run**: a heavy run given `gate run --builder <host>`, which goes to that builder alone and ends failed (exit 1) rather than run elsewhere; its `queue` journal line carries `"pinned": true`.
- **Pipe-closed stop**: the box's stop of a job whose client's connection closed: `gate box run` terminates the job, waits for its processes and exits 255.
- **Plain part**: a name of a path's part that Windows creates under that very name and git does not own: not empty, no trailing dot or space, none of `\ : < > " | ? *`, no control character or bidirectional mark, no `~` before a digit, not `.git` and not a device name. A plain path has at most 64 parts, each plain; a routed run brings back only plain paths.
- **Pool**: the set of slots of one kind (heavy, light, remote); pools never wait on each other.
- **Pool id**: the first 8 lower-case hex digits of the SHA-256 of a `builders` entry's lower-cased alias (`mac-1` is `1f0efc62`), naming that builder's own remote pool in its claim files (`gate-remote-<pool id>-slot-<n>.json`), mutexes and tickets' `pool` field; `host` has none and keeps `gate-remote-slot-<n>`; a `hosts` entry has one. `PoolId` in `gate-state`.
- **Pre-banner failure**: an ssh call, or a git call over ssh, that ended before the builder's sshd sent its banner (status 255, or 128 for git, with empty stdout, no start marker and a first stderr line naming the banner exchange); the remote client retries it once after 2 s.
- **Preflight**: the box's first call of a routed run (`gate box preflight`): it creates the bare repo and the work folder and reports the gate version, the boot time, the SDKs and the tools its payload's `Needs` name.
- **Probe**: the box preflight's run of a tool's own version command (`node --version`) to learn whether the builder has the tool and which version, said as a `gate: remote tool` line; not a Probe by open.
- **Probe by open**: reading whether a slot is held by opening its mutex's name: it is held while any handle to that name exists.
- **Profile**: how the remote client speaks to one builder (`Profile` in `remote/transport.rs`): its alias, `os` and root, which set its path form, box line, pack commands, push URL and the folders under the root; made by `Profile::of(builder, transport.root())`. Not the builder's cache id, which names its PC cache folder.
- **Program name**: what a routed command's first word becomes when it names a program by an absolute path outside the worktree: the file name with a trailing `.exe` removed, which the builder looks up on its own `PATH`; the run says `gate: routed {given} as {name}`, and a name the router refuses leaves the word outside.
- **Progress**: what resets the stall clock in a sample: the output size changed, the job's CPU reached 1% of one core over the stall window since the last progress, a new pid appeared, a nested gate is paused, or the job holds a live nested gate.
- **Prune**: `gate box prune --root <folder>`, which the builder's scheduled task `\build-box\gate-prune-work` runs every 6 hours, or with `--keys <key>...` removes just the named keys whatever their age; the age form removes the key folder of every work-folder key idle for over 24 hours (its records first, then the folder, by rename into `{root}\pruned` and delete), keeping the key's `.lock`, and deleting no ref; only the keyed form deletes the key's `refs/gate`, `refs/gate-bridge` and `refs/gate-back` in the root's bare repositories. Not the box's day-old prune of stages and old outputs archives.
- **Pure crate**: a crate with no Windows types in its API that builds and unit-tests on Linux as well (`gate-state`, `gate-watchdog`, `gate-args`, `gate-router`).
- **Push**: `gate push`, which copies the installed `gate.exe` and desktop helper to every builder on the builders list over ssh, installs them there, into the admin-owned `C:\Program Files\gate\bin`, with the old files set aside and registers the desktop task; a macOS builder instead gets the commit `source.json` names git-pushed to it and its `gate-box` built there. Not the remote client's push of a snapshot to the builder's git repo.
- **Push lock**: the file `push.lock` in `%LOCALAPPDATA%\gate\bin` on this PC and in `C:\Program Files\gate\bin` on a builder, opened unshared by `gate push` (on this PC, around its read of the exe, and on each builder, for the whole install) and on this PC by `tools/install.ps1`, so only one of them changes or reads that folder's gate.exe at a time; the open handle is the lock, and the file stays.

  It is opened without following a link, and a link, a folder, a junction or a hard link there is refused.
- **Quarantine (sync-back)**: the folder `objects\incoming-gate-<pid>-<start ms>-<nonce>` in the repository's object store that a sync-back's fetch writes into, so no object reaches the real store unless the back commit is kept or applied; deleted at the sync-back's end, or kept with a `gate-kept` mark when moving its objects failed, until a later sweep removes it.
- **Reason**: the free text `gate run --reason "<why>"` (`-Reason`) that a `--local`, `--slot critical` or `--alone` run must give, and that any run may give; recorded on the run's `queue` line, in its claim and in its ticket, and shown on ops-tower's Gates page.
- **Recorded escapee**: an escaped process the watch's samples recorded (pid, start and the parent it was seen under), which every kill of the running command ends with what is under it, though the process of the job that started it has ended; one whose launcher ended before the first sample is found through the launcher's departed member instead.
- **Refusal**: a builder's or the remote client's answer that a routed run cannot run there, with a reason (`busy`, `unreachable`, `parity`, `rebooted`, `tools`, `layout`, `version`, `client`, `inputs`, `desktop`, `install`, `root`); the gate then falls back to a local run.
- **Refusal tag**: the stderr line `gate-remote-refused: <nonce> busy|tools|layout|inputs|sent|desktop|install` that `gate box run` says just before the human line of a refusal; the remote client reads a fallback of that reason from it alone, and ignores it once it has heard the start marker.
- **Release**: see take.
- **Remote client**: what `gate run` calls to run a routed command on a builder: `RemoteClient` in the gate binary; every routed run uses the Rust client over ssh, which looks for ssh when the run routes, and a client that cannot start makes the run fall back with reason `client`.
- **Request**: what a `gate box` call is asked, the payload as the first line of the call's stdin, never a word of the ssh command line.
- **Restore file**: a file of an `obj` folder whose name ends `.nuget.g.props` or `.nuget.g.targets`; the builder's own copy stays when a sent build lands, and a put never deletes or replaces one.
- **Rollover**: the move of `events.jsonl` over `events.1.jsonl` by the append that finds the journal at or above 5,242,880 bytes, followed by the archive of the rolled file.
- **Root hash**: the first 8 hex digits of the SHA-256 of a non-default state root's path, carried in every kernel object name and slot marker of that root.
- **Root-relative path**: a path with a single leading `\` (or, where a value begins, `/`) and no drive, which Windows resolves against the current drive's root; the router counts it outside the worktree.
- **Routed lock**: the mutex `Local\gate-[<root hash>-]routed-<16 hex>` (the hash of the lower-cased work-folder key) that a routed run takes before its remote slot and until its remote attempt ends, waiting up to 90 s for a holder; a run that finds it still taken past the bound, or held by a warm-up, runs here with reason `busy`.
- **Routed run**: a heavy gate whose command `remote.json` sends to a builder.
- **Routing file**: `remote.json` in `%LOCALAPPDATA%\gate\`, naming the builder's host (and, for `gate push`, further `hosts`), the remote pool's size and, per repo, the `-like` patterns of the commands that route the globs of the files a routed run brings back and the sibling folders it may carry (machine consent).
- **Routing hint**: the line after any cores line saying a passed light run of 30 s or more would have been sent to a builder by `remote.json` on heavy: `gate: ran <n> s on a light slot; on heavy, remote.json would send this command to a builder`.
- **Run end**: what a gate does once its command has exited and its status is taken, before its verdict is reached: it ends every process the command left in its job with exit code 124, sparing every member whose image is `gate.exe` with its tree, its job and the job members above it (its launcher), and console hosts (`conhost.exe`) on their own, both names compared ASCII case-insensitively.
- **Run folder**: the folder `gate run --cd <folder>` (`-Cd`) makes the gate enter before any slot is taken; routing, the command's working folder, a fallback's local run and the journal's and claim's `cwd` all take it as the folder the gate was started in.
- **Run id**: `gate-{pid}-{start ms}`, with `-{root hash}` under a non-default state root, and `gate-box-<Nonce>` for the command `gate box run` runs; the command gets it as `SharedCompilationId` and `MSBUILDNODEHANDSHAKESALT`, so its MSBuild nodes, and a compiler server if a project turns shared compilation back on, are its run's own; it also gets `MSBUILDDISABLENODEREUSE=1` and `UseSharedCompilation=false`, so no node or compiler server idles in its job after a build.
- **Run temp folder**: the private `/tmp/gate.XXXXXXXX/` folder the Unix box makes for each run and sets as its command's (and tool restore's) `TMPDIR`, so .NET's Unix-socket named pipes fit the 104-byte path limit; it is removed when the run ends, and no folder is made when the caller's `--env` sets `TMPDIR` ([design.md](design.md#the-unix-box)).
- **Run trace**: the optional fields of a `release` line saying where the run's time went: the job's CPU seconds and process counts, the command's priority class, the load-free share, the long `children` (command lines redacted of secrets, best-effort) and, for a routed run, its `phases`; see [Journal](design.md#journal).
- **Sample**: one reading of a running command taken every 5 s by the sampler: the system's CPU times, the job's CPU and pids, and the log's size, stamped `began` before its reads and `at` after them; the watchdog's clocks advance only by samples.
- **Sampler**: the platform side of the watchdog that takes the samples (Win32 on the Windows box, the Mac's CPU-load counters in the Unix box); if one fails, the watch goes by wall time alone.
- **Script word**: a command word holding a line break or one of `, ; " ' ) | & < >`, such as a script's text or a list; in it a path ends at white space, where in any other word a path runs through its spaces.
- **SDK pin**: the `sdk` member of a snapshot's `global.json` (version, `rollForward` policy, `allowPrerelease`) that the parity check resolves against the builder's SDKs; one that cannot be read leaves only the SDK major to check.
- **Sent build**: the PC's `<project>/bin/<configuration>` build and the project's two restore files, sent to a builder after the inputs so a routed `dotnet test --no-build` of a repo `remote.json`'s `sendBuild` lists keeps its `--no-build` there; the box holds it in the `<Work>.sent-build` record, and a run's `SentDigest` is checked against it.
- **Session 0**: the Windows session the builder's box runs in, which has no interactive desktop; a command that needs a screen is a desktop run's, created in the console session instead.
- **Shadow end**: the expected end of the slowest gate a critical drain waits on, which closes the lent window.
- **Shim**: an extensionless script on PATH, such as the bash shims a plugin puts ahead of `uv` and `python`, which program resolution skips since Windows cannot start it.
- **Sibling**: a worktree beside the repo's root (`../<name>`) that its `.gate/siblings.toml` declares because the build reaches into it by relative path; a routed run needs the machine's consent for it and a real folder of it beside the root, and a word naming a path inside it is rewritten for the builder's layout.
- **Slot**: a named mutex in the session's `Local\` namespace that a gate holds for its command's whole run; the number of slots per pool caps how many commands run at once.
- **Slot marker**: the environment variable `GATE_SLOT_HELD`, `<kind>:<pid>:<start>` (plus the root hash under a non-default root), which a gate sets for its command so a nested gate knows its parent.
- **Snapshot**: either the parentless commit of a worktree as it stands, which a routed run sends to its builder; or the critical gate's record, at take, of the counts and the other gates' claims.
- **source.json**: the file `%LOCALAPPDATA%\gate\bin\source.json` that `tools/install.ps1` writes beside the installed `gate.exe`, recording the repo root and the commit the installed gate was built from (`repoRoot`, `commit`, `buildId`, `dirty`) ([design.md, Install](design.md#install)); `gate push` reads it to know which commit to build on a macOS builder.
- **Spawn lock**: the `gate-win32` lock held while the gate starts any process, so only the launched command inherits the copies of its handles.
- **Stable line**: one of the three published `gate:` line forms callers may parse (STALLED, TIMED OUT, TRANSFER TIMED OUT or BACKSTOP; `waiting for the machine (critical)`; `Full output:`); every other `gate:` line is prose.
- **Stage**: the install's folder `<worktree>\.tmp\<key>-<nonce>` (the outputs stage), where a fetched outputs archive is unpacked, its copies made and its members checked before any file is moved into the worktree; or the box's inputs stage, where a put's archive is unpacked before its files are moved into the work folder.
- **Stages folder**: `<root>\inputs-stage` (elevated box) or `<root>\inputs-stage-medium` (unelevated), the folder holding the inputs stages, made with a protected owner, DACL and label; one the box did not make refuses the put (`cannot use <path>: its owner, DACL or label is not the box's; remove it`).
- **Stale folder**: a PC-side folder that a judging glob of a passing routed dotnet build stops at and whose matching files the run did not bring back; the `gate: routed build left stale: ...` line names them.
- **Stale record**: a job record that no longer names the group its run made (no such process group, one the box may not signal, written before the boot, a reused pid, or a gone leader with no member in the recorded session); a run removes it under the work lock and `stop` ignores it ([design.md](design.md#the-unix-box)).
- **Stall**: a kill for no progress (no output, CPU or new process) for the stall window, `--stall` seconds.
- **Stand-in**: a live covered gate whose command holds a nested gate and whose own slot kind covers it, which that gate runs under in place of its ended parent gate, so one build tree holds one slot; only a covered marker with `kind` `heavy` or `light` is one.
- **Stand-in helper**: `fake-desktop-helper.exe`, the real desktop helper's code built with `test-seams`, which the box's `--test-box-desktop` seam starts in place of the registered task so a suite case can run a desktop run without a task or a second session.
- **Start marker**: the stderr line `gate-remote-started: <nonce>` that `gate box run` says just before it launches the command; a run call that carried it is never retried and is not a pre-banner failure.
- **State root**: the folder holding every file the gate writes, `%LOCALAPPDATA%\gate\v1\` by default, overridden by `--state-dir` or `GATE_STATE_DIR`.
- **Stop event**: the manual-reset event `<box job name>-stopped` that `gate box run` creates before its job and `gate box stop` sets before it terminates the job, so a launch that finds it set ends the command unstarted.
- **Stop-tree**: `gate stop-tree <pid>`, which terminates the gate jobs and then the processes of a pid's tree, deepest first, so a kill reaches processes that no longer have a parent.
- **Subst chain**: the drives a `subst` drive leads to when its target is itself on a `subst` drive, followed at most 26 hops with a visited set; a cycle, an unreadable device or a target that is not a `\??\` path gives no spelling, and the run stays local.
- **Sweep (desktop)**: the box's selection, after a failed hand-off to the builder's desktop, of the processes still to end: those whose parent is the helper, created after it and in the console's session, as `(pid, created)` pairs the caller re-checks through its own handle before asking each to end, then waits for them all within one end limit for the whole sweep.
- **Sync-back**: applying the files a routed command changed on the builder to the PC's worktree, refused when the worktree changed during the run; a pair's is all or nothing across its repos, applying only the back commits the box's back commits line names.
- **Tagged line**: a `gate-remote-<tag>: ...` line the box writes on stderr for the client: `started`, `refused`, `heartbeat`, `outputs`, `killed` (the box killed the command, naming the run's nonce and `timed-out` or `backstop`) and `adjusted` (naming the run's nonce and the load-adjusted seconds the box counted).
- **Take**: a gate acquiring its slot, journalled as `take`; **release** is letting it go, journalled as `release` before the slot is freed.
- **Take-back**: undoing a bad install by reinstalling the previous commit with `tools/install.ps1`; the PowerShell gate it once returned to is gone.
- **Tally**: the Unix box's CPU source's count of the command group's CPU, each process once: the processes read at the last tick by (pid, start), plus a retired sum of those that vanished with their reaper outside the group; it only rises (`cpu.rs`).
- **Test map**: [test-map.md](test-map.md), which maps each source area to the suite modules and unit tests that reach it, as nextest filtersets; a step's proving loop runs only those, and so does an item's last gate in test mode `unstable`.
- **Test mode**: the `gate-nextup` profile's `test mode: unstable|stable` line; `unstable` runs each item's reached tests and the full suite before a push or reinstall, `stable` runs the full suite for every item.
- **Test seam**: a hidden `--test-*` flag, compiled only with the `test-seams` cargo feature, by which the suite sets a timing knob or prints the parsed request.
- **Ticket**: the JSON file `waiting\<pid>-<start>.json` a gate writes when it queues for a slot, holding its kind and `arrived` time; waiters of one kind take slots in ticket order.
- **Toolchain manifest**: a repo's `.gate/toolchain.toml`, naming the tools (each with a minimum version, or present at any) and the .NET workloads a routed run's builder must have, and optionally an `[env]` of engine env names; read by `remote/toolchain.rs`; `gate check` reads it from the worktree, and a routed run with parity from the snapshot's tree, refusing the route when the builder lacks a declared tool.
- **Tracked member**: a member of a routed run's fetched outputs archive whose path the worktree's git index holds, or that sits under a submodule or a nested repository; the install skips it (`... is tracked by git`) unless a `--bring-tracked` glob of the call matches it.
- **Transfer ceiling**: the fixed 1800 s limit on a routed run's transfers, whatever `--timeout` says: the setup (preflight and push) counted from the attempt's start, each fetch after the run call and each inputs call counted from its own start; a fetch past it ends TRANSFER TIMED OUT (exit 124, verdict `transfer-timed-out`), a setup call past it falls back `unreachable`, an inputs call past it falls back `inputs`.
- **Trusted Git bin**: the `bin` folder of the Git install the builder's box finds, used only when it lies outside the run's own folders and every `.exe` in it, with the shell's own `usr\bin` and `mingw64\bin` files, passes the installed-file check; `gate box run` puts it first on each command's `PATH`, so a bare `bash` is Git's and not WSL's launcher in the system folder.
- **UE_ROOT**: the variable a routed run with an `UnrealVersion` sets, for every command, to the folder of the builder's engine install it resolved under `GATE_UNREAL_ROOT`; a run without a version has any inherited value removed, and the caller cannot send it with `--env`; the engine env names get the same folder.
- **Unbound marker**: a `GATE_SLOT_HELD` marker naming a live gate whose job does not hold this gate or the first ancestor of it that any job holds; the gate ignores it and runs as one under no parent. A marker whose binding cannot be judged is honoured, not unbound.
- **Unix box**: the box of a macOS builder, `gate-box` (crate `gate-box-unix`); it speaks the Windows box's wire under `PathForm::Unix`, builds `preflight`, `boot`, `run` and `stop` (a sibling pair included), and judges its work root by owner and mode ([design.md](design.md#the-unix-box)).
- **Usage error**: a command line the gate refuses (a missing, unknown, repeated or invalid input): each problem on its own `gate: ` line, then the usage, exit 2, before any slot is queued.
- **Verdict**: the outcome a `release` line records: `passed`, `failed`, `log-failure`, `stalled`, `timed-out`, `backstop`, `transfer-timed-out` or `unknown` (no run facts).
- **Wake event**: the auto-reset named event each waiter sleeps on, which a gate signals when it takes or releases a slot or deletes a dead gate's ticket.
- **Warm**: said of a work folder whose warm-up passed on the builder for this host and this `.gate/warmup.toml`; its warm-up record has state `warm`, which `gate warm` writes once the builder confirms the warm-up.
- **Warm record**: the builder's file `{Work}.warm`, holding exactly the hash of the warm-up file whose commands last passed in the work folder; the box's preflight says it as `gate: remote warm <hash|none>`.
- **Warm-up**: the commands a repo's tracked `.gate/warmup.toml` declares, run on the builder in a worktree's work folder before routed work for it, so a short-ceiling routed run meets an incremental build; it needs the repo named in `remote.json`'s `warmup` list. `gate warm` runs one by hand and writes the record; no route starts one, and a routed run goes to the builder whatever the record says. `gate check` reads the record through the router's judge.
- **Watch call**: the one remote-client call (`preflight`, `push`, `inputs-diff`, `inputs`, `run`, `ls-remote`, `fetch` or `outputs`) that `--test-remote-watch-call` points the stall and ceiling seams at: the command's ceiling for `run`, the transfer ceiling for any other.
- **Watchdog**: the part of a running gate that samples the command and kills its job on a stall, the ceiling or the backstop.
- **Win32 layer**: the `gate-win32` crate, the only code that calls Windows for job objects, processes, mutexes, events and console handling.
- **Work folder**: the builder's checkout of one PC worktree, reused across routed runs so builds stay incremental.
- **Work lock**: the Unix box's `<Work>.lock`, an exclusive `flock` on a plain file of one hard link that a run holds for its life, so one run at a time uses a work folder; another's hold is the `busy` refusal. The Windows box's is the work-folder lock.
- **Work root**: the folder `<root>` holding the builder's work folders (`<root>\work\<key>`) and bare repositories; the box's preflight refuses one another account may write in, or whose folders above it another account may delete, and holds it for the run (`gate: the builder's work root is not locked down: <why>`), and the installer's "Gate work root" step locks it.
- **Work-folder key**: the name of a work folder: the worktree folder's name plus 8 hex digits of the SHA-256 of its lower-cased path.
- **Work-folder lock**: the file `<Work>.lock` that `gate box run` opens with no sharing and holds for the run's life, so one run at a time uses a work folder; a held lock is the `busy` refusal.
- **Worktree lock**: the mutex `Local\gate-[<root hash>-]worktree-<volume>-<file id>`, named for a worktree folder's id, that a routed run takes for its main root and each sibling, in id order, from before its snapshots until its last push is saved, and a sync-back takes again for each worktree it has a back commit for, from before its fetch to its end, so two runs never write one folder at once; another run's hold is waited for up to the git limit.
- **Worktree record**: the PC's JSON file `remote\<key>.worktree` in the state root, written once by a routed run before its first builder call, mapping a work-folder key (a one-way hash) back to the worktree root, git common folder and repo it was made from, with the time of the last routed run; only the routed run reads it, to decide whether to rewrite it, and nothing removes it yet.
- **Wrapper**: a repo's copy of this repo's `tools/gate.ps1`, the only way anything calls the gate: it hands every word to the installed gate.exe, and on a machine without one runs the command directly, without slots or watchdog.
